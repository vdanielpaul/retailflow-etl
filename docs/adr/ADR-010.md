# ADR-010: Terraform Bootstrap Strategy

## Context
Deploying infrastructure via Terraform presents a bootstrapping challenge: remote GCS state backends require an existing GCS bucket, but that GCS bucket is itself infrastructure that must be provisioned.

## Decision
We implement a three-phase bootstrap strategy:
1. **Phase 1 (Local State)**: Start with a local backend configuration (`terraform.tfstate`) to allow Terraform to initialize and run without cloud dependencies.
2. **Phase 2 (State Bucket Provisioning)**: Declare a dedicated, infrastructure-only `tfstate` bucket resource inside the storage module. Enable versioning and keep 10 recent state versions.
3. **Phase 3 (State Migration)**: After the state bucket is provisioned, uncomment the `gcs` backend configuration in `backend.tf` and run `terraform init -migrate-state` to migrate state.

## Consequences
- No dependency loop on GCP resources.
- Clear separation between the infrastructure state bucket and RetailFlow application data buckets.
- Fully automated state tracking after initial bootstrap.
