# ADR-009: GCS Storage Design

## Status
Approved

## Context
RetailFlow ETL requires staging storage for incoming files, successfully processed records, and quarantined bad feeds. We must select optimal storage classes, locations, and lifecycle retention parameters to balance performance, cost, and operational simplicity.

## Decision
1. **Locations**: Use regional storage locations (co-located with Dataflow and Cloud Functions). This eliminates cross-region egress charges and maximizes write performance.
2. **Storage Classes**:
   - **Raw Bucket**: `STANDARD` (Frequent reads by nightly pipelines).
   - **Quarantine Bucket**: `STANDARD` (Frequent access by developers during debugging).
   - **Archive Bucket**: `NEARLINE` (Operational backups are written once daily and rarely read again).
   - **State Bucket**: `STANDARD` (Accessed on every deployment run).
3. **Retention & Lifecycles**:
   - **Raw**: 30 days.
   - **Quarantine**: 90 days.
   - **Archive**: 180 days (Operational retention window for data reconciliations and backfills).
4. **Access Control**: Enforce `uniform_bucket_level_access = true` and `public_access_prevention = "enforced"`.

## Consequences
- Cost-efficient storage management using auto-expiration lifecycle rules.
- 50% storage fee reduction on the archive bucket by adopting the `NEARLINE` storage class.
- Consistent security profile blocking public access.

## Alternatives Considered
- **Standard Storage Class for Archive Bucket**: Rejected due to unnecessary high storage costs for rarely read analytical backups.
- **Multi-Regional Locations**: Rejected due to higher storage unit pricing and inter-region network charges during ingestion.
