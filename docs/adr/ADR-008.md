# ADR-008: Storage Naming Strategy

## Status
Approved

## Context
Google Cloud Storage (GCS) bucket names are globally unique across all GCP projects. Using standard naming conventions like `retailflow-dev-raw` is highly likely to cause conflict errors during deployment if other users have provisioned those exact names.

We need a consistent naming convention that:
1. Satisfies global uniqueness.
2. Identifies the project and environment.
3. Exposes readable, standardized suffixes.

## Decision
We adopt the namespace prefix naming convention:
```text
${var.project_id}-retailflow-${var.environment}-${var.bucket_purpose}
```

Example names:
- `myproject-retailflow-dev-raw`

### Naming Constraints:
- Enforce lowercase alphanumeric characters and dashes (`-`).
- Limit names to under 63 characters to satisfy GCS length limits.

## Consequences
- Guaranteed global uniqueness because GCP Project IDs are globally unique.
- Simplifies access controls and billing analysis by organizing resources under a single prefix.

## Alternatives Considered
- **No Project ID Prefix**: Rejected due to high risk of naming collisions.
- **Project ID as Suffix**: Rejected as it makes resource sorting and readability less clean in GCP Console search filters.
