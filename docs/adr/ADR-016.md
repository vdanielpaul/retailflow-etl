# ADR-016: Event-Driven File Ingestion Trigger

## Status
Approved

## Context
RetailFlow ETL v2.0 requires an event-driven system to detect POS CSV raw files immediately upon landing in GCS. Standard file-polling mechanisms require scheduled batch runs, introducing latency and operational CPU costs. 

We need a low-cost, serverless integration to notify downstream services as soon as a new GCS object is finalized.

## Decision
We implement a two-topic, event-driven GCS-to-Pub/Sub trigger pipeline using native GCP integrations:
1. **GCS Storage Notification**: Configure `google_storage_notification` to bind the GCS raw bucket upload events (`OBJECT_FINALIZE`) to publish raw message notifications to a dedicated raw ingestion topic (`retailflow-${var.environment}-ingestion-events`).
2. **System IAM Authorization**: Retrieve the system-managed GCS service account using `google_storage_project_service_account` and assign it `roles/pubsub.publisher` on the ingestion events topic to allow publishing messages.
3. **Thin Cloud Function Coordinator**: Implement a lightweight Cloud Function triggered by the raw ingestion events subscription. The Cloud Function extracts file metadata, calculates the file content SHA-256 hash, and queries BigQuery's watermark log.
4. **Processing Events Topic**: If the file hash is confirmed to be **NEW** (no duplicate detected), the Cloud Function registers the ingestion watermark and publishes a structured processing event to a separate topic (`retailflow-${var.environment}-processing-events`), which triggers downstream Dataflow batch ingestion. If a duplicate is detected, the run terminates.

## Consequences
- Decoupled triggers: Raw storage notifications are fully isolated from active downstream processing queues.
- Ingestion-level duplicate prevention: Duplicate files are caught and terminated at the trigger boundary, avoiding running expensive Dataflow clusters for duplicates.
- Reliable delivery: Pub/Sub buffers message logs for up to 7 days if the Cloud Function or downstream Dataflow are temporarily unavailable.

## Alternatives Considered
- **Single-Topic Trigger Ingestion**: Rejected because it mixes raw storage notification events directly with active execution triggers, meaning downstream systems would receive alerts for duplicate uploads.
- **Poll-Based Scheduler Ingestion**: Rejected because polling GCS buckets adds execution complexity, API charges, and latency.
